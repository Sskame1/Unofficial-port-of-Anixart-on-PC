# Windows-клиент Anixart: MVP просмотра одного видео

**Дата:** 2026-10-26  
**Статус:** вариант 1 одобрен для проработки; требуется пользовательская проверка этого проектного решения перед реализацией.

## Цель

Создать небольшой Windows x64-клиент на Rust, который без Android-эмулятора получает один эпизод Anixart гостевыми запросами, разрешает поддерживаемый Kodik URL в прямой HTTP-поток и запускает его в бесплатном mpv. После запуска доступны пауза/продолжение, перемотка и закрытие.

## Границы MVP

- Только Anixart API и один провайдер: Kodik.
- Гостевые API-запросы; аккаунт и токен не добавляются.
- Без каталога, поиска, истории, синхронизации, выбора нескольких источников и автоматического next/previous.
- Для проверки используются доступные записи Anixart: релиз `19053`, тип `2` (AniLibria), источник `7` (Kodik), эпизод с `position=1`. Эти ID задаются как изменяемые значения; их можно заменить аргументами запуска или в UI.
- Декодирование/обход DRM, рекламы, CAPTCHA или геоблокировки в объём не входит. Если провайдер не выдаёт воспроизводимый URL обычным запросом, MVP сообщает об ограничении.

## Предлагаемая архитектура

1. **Минимальный интерфейс Rust.** Небольшое окно с полями release ID, type ID, source ID, episode position и кнопкой запуска; строка состояния показывает этап и понятную ошибку. Поля по умолчанию заполнены проверенными ID. UI не является поисковым каталогом.
2. **Клиент API.** Получает базовые URL из `GET config/urls`, далее по очереди вызывает `GET episode/{releaseId}`, `GET episode/{releaseId}/{typeId}` и `GET episode/{releaseId}/{typeId}/{sourceId}?sort=0&token=`. Из ответа выбирает эпизод с указанной позицией и проверяет `iframe`/URL. JSON-модели и HTTP ошибки находятся в отдельном модуле.
3. **Адаптер Kodik.** Для единственного разрешённого host повторяет только установленный из APK путь `KodikParser`: запрашивает URL через HTTP с совместимыми User-Agent/Referer, извлекает стандартные варианты качества и необходимые заголовки/cookies. Никакой универсальной поддержки сайтов или выполнения HTML/JavaScript.
4. **Плеер mpv.** Rust запускает установленный/рядом лежащий Windows mpv runtime в отдельном окне и передаёт прямой URL с Referer/User-Agent/cookie, если они нужны. Rust-приложение управляет процессом через JSON IPC: play/pause, seek и quit. Если mpv отсутствует, UI показывает точную инструкцию по установке/пути.
5. **Конфигурация и лицензии.** URL сервиса и ID для воспроизведения не вшиваются в DEX и не содержат секретов. README перечисляет Rust crate licenses и лицензию используемого mpv/libmpv runtime вместе с происхождением двоичных файлов. До распространения проверяется точная конфигурация выбранной Windows-сборки, включая FFmpeg/кодеки и обязательные notices.

## Выбор видеодвижка

Кандидат — mpv. APK-плеер работает с HLS, DASH и progressive media sources; MPV поддерживает распространённые HTTP/HLS/DASH потоки и принимает Referer/User-Agent/cookie для запросов. Это делает его подходящим для конечной прямой ссылки Kodik, если её формат и заголовки подтверждаются экспериментально.

Для первого MVP предлагается запуск отдельного процесса mpv и управление им по IPC, а не встраивание `libmpv` в поверхность Rust-окна. Это сохраняет готовое окно и стандартные элементы/клавиши mpv, не требует низкоуровневого рендеринга видеокадров в Rust UI. Отдельный плеер должен иметь лицензию mpv (проект предоставляет LGPL 2.1-or-later вариант для libmpv; конкретный runtime и связанные зависимости проверяются до фиксации поставки). Если IPC/поставка выбранной Windows-сборки не подтвердятся, до реализации будет сообщён технический блокер.

## Обработка ошибок и ограничения

- Ошибки API, отсутствие типа/источника/эпизода, неподдерживаемый URL, недоступный Kodik, отсутствующий mpv и отказ запуска отображаются в строке статуса без утечки ответов или cookies.
- Временные ссылки и cookies держатся только в памяти на время запуска; не записываются в лог/на диск.
- Без входа подтверждены публичные чтения API-ответов и получение ссылки эпизода. Фактический поток mpv пока не подтверждён.
- APK указывает на множество источников; другие провайдеры этим MVP не поддерживаются.
- Сам сервис может менять API/провайдера, ограничивать трафик/регион или прекращать выдачу ссылок.

## Проверка готовности

Пользовательская проверка сборки и работы включает: сборку Windows x64, реальный гостевой запрос к API по указанным ID, разрешение Kodik URL, запуск mpv и проверку ненулевого playback-time; затем проверку паузы, продолжения, seek и закрытия. Заявление о работающем видео допускается только при наблюдаемом старте воспроизведения. Отдельно перечисляются лицензии зависимостей и точные команды запуска.
